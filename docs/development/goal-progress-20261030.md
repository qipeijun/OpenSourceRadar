### 已实现

- 配图：每个平台固定三张槽位（封面主图、功能场景图、使用条件提示图），一次 HTTP 调用只推进一张；
  失败写入失败记录并保留同批已成功图片，可只重试失败那张。整套生成在前端循环，
  单次点击最多三次调用，循环以本地槽位判定为唯一依据，不信任响应字段，避免异常返回时连续付费。
- 单张修改默认把该图本身作为 `input_image` 编辑输入；显式勾选参考图时改用参考图。
  修改与恢复都新增记录，旧图文件不删除，恢复复用同一文件。
- 参考图上传：按文件头识别 PNG/JPEG/WEBP 并要求扩展名一致，伪装文件拒绝；
  只提供已登记文件名，读取路径由服务端拼定。
- 提示词硬性要求原创插画、不得伪造真实界面截图、运行结果、终端输出、用户数、收益或评价，
  画面文字最多使用所选标题且须逐字准确。
- 视觉风格：全局可复用配置 + 项目级覆盖；项目级未设置时展示“沿用全局”，不伪造项目副本。
- 服务信息之外新增“文案更新后询问是否同步重做配图”，只有经营者点确认才发起生图，不自动重画。
- 导出：`GET /api/projects/:id/export?version=` 支持重复参数一次导出多平台选定版本；
  自研 STORE 方式 ZIP（不引第三方依赖，PNG 已压缩），文件名 UTF-8 标记，
  同平台多版本自动加版本短号避免包内覆盖。包内只有 `文案.txt` 与成图，
  不含证据 ID、内部资料、服务配置或研究备注（测试断言）。
- 设置页新增配图服务与三项能力状态：分析、检索、生图分别显示
  “最近一次真实调用成功/失败 + 模型 + 时间 + 失败原因”，无记录即显示尚无真实调用记录；
  切换分析服务不改动检索与配图两行（有测试）。
- 能力记录持久化在 SQLite settings 中，由真实调用结果写入，不来自配置推断。
- 图片下载响应头此前把中文与 `/` 直接写入 `content-disposition`，会抛
  `ERR_INVALID_CHAR`；改为 ASCII 回退名 + RFC 5987 `filename*`。
- 修订配图接口时发现的契约不一致：`imageId` 同时在 URL 与请求体要求，导致恢复请求 400；
  统一以 URL 为准。
