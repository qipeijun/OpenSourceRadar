## 开发顺序与完整切片

以下为重新整理的工单候选，尚未发布；各项均包含数据处理、持久化、接口、网页展示与相关验证。首个里程碑必须完成 T01–T04，不能以只有榜单或手动链接分析器作为首版交付。

| 编号 | 任务 | 阻塞项 | 交付与验收 |
| --- | --- | --- | --- |
| T01 | 自动发现真实项目并展示候选 | 无 | 从 GitHub Trending 读取候选、归并仓库、保存来源和发现时间，在本地网页展示；用户无需提供链接；请求失败、页面解析失败与真实空结果可区分，重复运行不重复建项目 |
| T02 | 从自动候选识别中国用户需求 | T01 | 获取项目材料，按三类场景初筛，生成中文用途、目标人群、门槛和需求证据；保留入选或排除理由；缺乏需求证据明确标记，不用热度替代需求 |
| T03 | 核验自动候选的中文教程缺口 | T01 | 展示中文检索词、时间、来源、摘要或全文覆盖范围与具体缺口，支持人工补充；同名误匹配、检索失败、未检索到和无法读取分别处理；不宣称全网没有教程 |
| T04 | 生成选题决策卡并保存人工判断 | T02、T03 | 综合材料输出目标用户、可做教程或部署帮助、时机、反证、成本未知项和下一步核验；保存是否实测及理由；历史不足仍可给有限定的建议，预测显示暂不可预测；重分析失败保留上一版且不覆盖人工决定 |
| T05 | 用自动发现的10个项目试评 | T04 | 从实际候选选择多种情况，记录证据可信、判断区分度与行动帮助；逐项保存评价和问题，不要求用户先找项目；样本不足如实报告，不以报告篇幅或推荐数量判成功 |
| T06 | 每日自动运行并恢复补采 | T04 | 本地服务运行时每日发现、初筛、限量分析；配置数量与运行时间；错过多日只补采一次当前数据，保存运行阶段和失败原因，不重复补跑或覆盖历史 |
| T07 | 查看真实趋势观测与缺口 | T01 | 保存实际采集时间和指标来源，展示历史变化与缺口；首次观测不算增长，缺测不补零，不混合榜单周期增量与 API 总量差值 |
| T08 | 筛选比较及手动补充项目 | T04 | 按场景、建议、门槛和证据完整性筛选比较，手动链接进入同一分析链路；手动入口不替代自动发现，已有仓库不重复创建 |
| T09 | 记录7天辅助预测 | T04、T07 | 对符合数据完整性规则的项目保存预测时点、前7天基线、目标期限、结论与依据；不足则暂不可预测，不阻断选题卡；容差等口径须在实施本项前固定 |
| T10 | 到期复盘预测 | T09 | 期限到达后按原口径计算并对照结果，缺失数据记录无法评价；不修改原预测或使用未来证据回填依据 |

T02 与 T03 可并行；T05、T06、T08 在 T04 后独立开展。T07 可在 T01 后开始积累数据，T09/T10 不阻塞首轮选题试评。T06 的自动数量与时区等参数在该任务实施前确定，不阻塞 T01–T04。

## 业务验收主线

自动发现 → 场景初筛 → 中文证据 → AI 选题建议 → 人工判断。系统负责找项目、收集材料与初步分析；经营者负责是否投入实测。最先证明的是能找到“升温且优质中文教程尚未跟上”的潜在选题，并说明服务谁、补什么缺口、交付什么帮助与先验证什么。

7 天预测只是辅助信号。安装复杂既可能构成可收费帮助，也可能造成高支持成本，不能机械加分或剔除。10 项目试评尚未执行，不代表商业效果或预测准确率已得到验证。

## 首版交互范围

工作台在经营者电脑本地运行，默认仅本机浏览器访问，供本人查看候选、阅读 AI 分析、比较项目、保存选题决定，并手动添加 GitHub 链接。暂不包含公众注册和付费系统，不部署服务器。

每日自动执行以电脑唤醒且本地服务运行为前提。验收需覆盖停机导致的观测缺口及最近成功采集时间展示，不能用恢复后的当前数据伪造缺失历史。恢复后若已错过采集，只补执行一次当前采集，不逐天补跑；未错过时不额外补采，也不按停机天数追加 AI 分析额度。

## 发布前检查

已确认的 AI 接入方向：通过可配置服务地址、模型名称和密钥支持 OpenAI、DeepSeek 等服务，记录每次分析实际使用的服务与模型。接口能力须核实，公开检索单独设计；密钥不进入仓库、浏览器响应或日志。具体初始模型待确定，不擅自加入自动降级或多模型并行评审。

已确认的前期投入原则：效果验证优先，AI 与公开检索暂不设金额预算上限；保留调用用量和可获得的费用记录，不默认削减必要证据获取。每日批次用于组织审阅，不能因无预算上限而无限重复分析。首轮试评方式已确认，具体样本及量化通过阈值待确定。

已确认的中文证据范围：公开检索与人工补充，不承诺全平台覆盖。结果展示关键词、检索时间、链接及覆盖限制；支持人工补充链接或摘录并标明来源。无法读取的内容标为未核验，不作为教程缺失证据；仅获取摘要时不声称已核验全文。

已确认的运行节奏：每天自动发现候选并更新趋势，基础筛选后限量进行完整 AI 分析，每日数量可配置；支持手动添加、立即发起分析和重新分析，展示分析时间与数据覆盖范围。具体额度、执行时间及排序细则尚未确认，正式拆票时须纳入相应端到端任务。

已确认的初筛原则：先按三个目标场景筛选，再综合增长信号、用途明确程度和已知使用门槛，保留入选理由；为新发现、历史不足的项目保留部分深入分析名额。中文内容缺口在深入分析中核验，初筛未找到教程不构成缺口证据。具体名额比例待确定。

已确认的跨任务验收要求：低门槛优先；高门槛项目仍可收录，但明确标注海外账号、付费 API、特殊网络或高性能显卡等条件及费用。AI 分别解释项目价值与使用难度，未知条件标为待核验，不得将未实测项目描述为已验证可用。
