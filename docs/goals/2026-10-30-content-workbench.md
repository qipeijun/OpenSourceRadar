## 执行任务与验收

1. **建立接入契约**：核实指定网关鉴权、Responses、模型目录、检索、生图和参考图编辑；保存脱敏契约与能力结果，区分不支持、网络失败与鉴权失败，不凭文本模型名推断图片接口。
2. **服务切换**：实现设置入口，显示分析服务、模型与能力；切换影响新任务，运行中固定启动配置；检索和生图独立展示，不静默切换或自动降级。真实请求验证路由及凭据隔离，历史结果保留，日志与浏览器响应无密钥。
3. **可靠分析与内部资料**：复核并修复审计中证据门槛、空检索结果、关键词误排除与完整输入溯源；生成中文用途、环境、依赖和限制，未知明确标记。反例测试与真实项目来源核对分别通过。
4. **双平台文案**：用户选题后生成可编辑草稿，使用公开服务信息；真实仓库功能有据，不泄漏内部备注，不虚构承诺。分别核验平台规则，无法核实时保持草稿，不标合规通过。
5. **配图和修改**：使用实际网关返回真实图片文件，保留提示词、模型、文案版本与时间。按指定范围修改，不覆盖人工编辑，部分失败保留已有成果。至少一项目完成双平台素材、一次文案修改、一次单图修改及旧版恢复；检查实际图片内容，不能只看接口成功。
6. **交互与导出**：清晰导航候选、详情、素材编辑和设置；保留列表筛选及返回位置；显示项目、平台、版本、保存与生成状态。未保存离开提示、禁止重复提交、失败可恢复。复制文案、单图下载和打包导出仅含选定对外版本。组件测试覆盖返回、编辑、版本、部分失败及重复提交；真实浏览器验证单独记录。
7. **真实效果验收**：从自动发现候选完成 10 项试评，不要求用户提供名单、不强行推荐。至少一个证据足够项目走通双平台导出，无合适项目时报告原因，不虚构样例。执行 `npm test`、`npm run typecheck`、`npm run build`，检查导出文件及版本关系。使用 `npm start` 前先检查并复用现有服务。
8. **积累趋势**：保存实际时间、指标与来源；区分日榜增量及累计 Star 差值，不补造缺测。覆盖重复采集、缺测与指标口径测试。
